# Полярик — прототип каталога

Версия 58. Статический прототип на HTML, CSS и JavaScript.

Распакуйте содержимое ZIP в корень репозитория. Все страницы и ресурсы находятся в `dist/`. Этот каталог можно отдавать любым статическим веб-сервером.

Для локального просмотра из корня репозитория выполните:

```bash
python -m http.server 8000 --directory dist
```

Откройте http://localhost:8000/. Локальный HTTP-сервер нужен для загрузки данных каталога из JSON. Устанавливать зависимости и собирать проект не требуется.

Личный кабинет, заказы и формы работают в демонстрационном режиме.

Скидка 5% на первый заказ не рекламируется и не применяется автоматически: индивидуальные условия согласует менеджер. Объёмная скидка и промокод суммируются. Для презентации кнопка «Войти» сразу открывает кабинет без логина и пароля. В корзине бонусы ограничены балансом и 30% товаров после скидок; минимальный заказ 5 000 ₽ проверяется до скидок. Ставка/порог начисления кэшбэка не утверждены. Рабочую идентификацию компании, начисление, списание и обмен с 1С необходимо реализовать на сервере.

Оформление юрлица содержит реквизиты РФ/Беларуси, контакты, город и адрес доставки. ТК выбирается из списка СДЭК, ПЭК, Деловые линии, Ozon или «Другая компания» с полем названия. Страховка требует явного выбора «Нужна» / «Не нужна». Для другого получателя вводятся ФИО одним полем и телефон. Эти данные сохраняются в черновике и подтверждении. Стоимость и сроки доставки согласуются индивидуально, способ оплаты — «Безналичный расчёт». В шапке показаны минимум и текущая сумма корзины.

Подтверждение формирует заказ с префиксом `ДЕМО-`, сохраняет снимок в sessionStorage, очищает корзину и один раз списывает тестовые бонусы. Последний демо-заказ доступен из пустой корзины. Проверка ИНН/УНП ограничивается форматом, запросов в реестры нет. Заказ, письмо, счёт и данные покупателя не отправляются на сервер; для запуска нужен рабочий заказ Битрикс, отправка уведомлений и обмен с 1С.

Основной переход «Перейти к оформлению» ведёт на отдельную страницу `order.html` с формой слева и итогом/кнопкой «Оформить заказ» справа, по структуре Аспро. Подтверждение отображается на этой же странице; последняя квитанция доступна по `order.html?receipt=last`. Прямой вход также проверяет минимум и наличие. На телефоне форма и итог идут последовательно. Быстрая покупка остаётся отдельной модальной формой.

## Проверки для разработки

Для запуска проверок навигации нужен Node.js:

```bash
npm ci
npm test
```

Эти зависимости нужны только для тестов. Для просмотра сайта по-прежнему достаточно статического HTTP-сервера.

Для Ozon показывается пояснение о согласовании тарифа менеджером; перечень тарифов и автоматический расчёт не заданы до уточнения у клиента.


## Корректировки встречи 19.11.2026

Полный попунктный реестр и остаток по контенту / бэку: [docs/2026-11-20-meeting-register.md](docs/2026-11-20-meeting-register.md).
Обновлены общие меню/подвал, шапка, дерево каталога, главная. Созданы `specials.html`, `gallery.html`, `looks.html`, `publications.html`. В кабинете сохраняются предпочтения ТК и необязательного тарифа, новое оформление использует их вместе с собственным черновиком. Тариф доступен для всех ТК; четыре перевозчика пока сохранены по прямому указанию пользователя. Историческая подсказка Ozon заменена универсальным полем.

`moderation.html` — открытый демонстрационный экран над локальными отзывами текущей вкладки; он нужен для проверки сценария согласования. Это не административный доступ к рабочим данным. В Битриксе редактирование/публикация/удаление должны требовать серверных прав сотрудника; новый отзыв остаётся неактивным до модерации.

Галерея ожидает фото/видео клиента; готов один демонстрационный макет образа с тремя товарами. Реальные 5–10 образов, материалы фотосессий, условия акций, перенос базы пользователей и интеграция 1С пока не выполнены. Порядок меню в прототипе редактируется в `catalog-tree.json`; серверный интерфейс сортировки и сохранение при обмене реализуются отдельно.
