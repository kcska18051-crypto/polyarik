# Полярик — прототип каталога

Версия 58. Статический прототип на HTML, CSS и JavaScript.

Распакуйте содержимое ZIP в корень репозитория. Все страницы и ресурсы находятся в `dist/`. Этот каталог можно отдавать любым статическим веб-сервером.

Для локального просмотра из корня репозитория выполните:

```bash
python -m http.server 8000 --directory dist
```

Откройте http://localhost:8000/. Локальный HTTP-сервер нужен для загрузки данных каталога из JSON. Устанавливать зависимости и собирать проект не требуется.

Личный кабинет, заказы и формы работают в демонстрационном режиме.

Скидка первого заказа: временная расчётная модель выбирает более выгодное из 5% и суммы объёмной скидки с купоном; совместимость 5% с другими скидками повторно открыта на согласование с клиентом. Для презентации кнопка «Войти» сразу открывает кабинет без логина и пароля. Вход для презентации открывает нового покупателя с 5% на первый заказ и нулевым бонусным балансом. Повторный вход сохраняет состояние использованной скидки. Прежний профиль повторного покупателя с тестовым балансом 1 500 ₽ остаётся отдельным примером в данных. Новая регистрация начинает новый профиль с 0 ₽. В корзине бонусы ограничены балансом и 30% товаров после скидок; минимальный заказ проверяется до скидок. Открытие оформления не списывает баланс и не расходует скидку первого заказа. Ставка/порог начисления кэшбэка не утверждены и не заданы. Рабочую идентификацию компании, начисление, списание и обмен с 1С необходимо реализовать на сервере.

Оформление юрлица содержит реквизиты РФ/Беларуси, контакты, ТК и город доставки. Доставка согласуется индивидуально, оплата — по счёту на расчётный счёт. Подтверждение формирует заказ с префиксом `ДЕМО-`, сохраняет снимок в sessionStorage, очищает корзину и один раз списывает тестовые бонусы/использует скидку первого заказа. Последний демо-заказ доступен из пустой корзины. Проверка ИНН/УНП ограничивается форматом, запросов в реестры нет. Заказ, письмо, счёт и данные покупателя не отправляются на сервер; для запуска нужен рабочий заказ Битрикс, отправка уведомлений и обмен с 1С.

Основной переход «Перейти к оформлению» ведёт на отдельную страницу `order.html` с формой слева и итогом/кнопкой «Оформить заказ» справа, по структуре Аспро. Подтверждение отображается на этой же странице; последняя квитанция доступна по `order.html?receipt=last`. Прямой вход также проверяет минимум и наличие. На телефоне форма и итог идут последовательно. Быстрая покупка остаётся отдельной модальной формой.

## Проверки для разработки

Для запуска проверок навигации нужен Node.js:

```bash
npm ci
npm test
```

Эти зависимости нужны только для тестов. Для просмотра сайта по-прежнему достаточно статического HTTP-сервера.
